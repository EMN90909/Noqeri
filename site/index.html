General by default

No OS mode, kernel mode or Linux-native assumption. Systems features are normal language features available where useful.

Low level is visible

Volatile memory, atomics, intrinsics and inline assembly cannot appear accidentally through a friendly API call.

Organization scales

Recursive file imports, module identities and inferred function generics add structure without turning basic scripts into ceremony.

Freestanding stays freestanding

Arrays, slices, status errors and atomics require no allocator, libc, Linux syscall layer or hidden OS runtime.

The remaining wall is coming down.

The capabilities that previously separated Noqeri from serious low-level and library work now have concrete language, type-checker, NIR and native-backend paths.

The ABI is Noqeri's boundary—not the language's crutch.

Raw memory and concurrency compile directly. The Noqeri ABI v2 remains an optional environment boundary for friendly services and embedding.

Language-native capability

  • fixed-width integers + pointer-sized integers
  • records with deterministic layout
  • pointers, indexing, casts and volatile access
  • arrays, slices and stack allocation
  • extern/export linkage
  • atomics, intrinsics and inline asm

Noqeri ABI v2

  • Noqeri-owned versioned contract
  • environment write/clock/platform callbacks
  • optional named services
  • no Linux syscall dependency
  • no AST/NIR/STL public layouts
  • usable by an app host, firmware or your own kernel
Design rule: add syntax when a concept belongs in the language across environments. Keep environment-specific conveniences behind the Noqeri ABI. Keep CPU-specific behavior explicit through named intrinsics or inline assembly.
