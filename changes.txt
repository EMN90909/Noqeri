BUILD ARCHITECTURE FINDING
The repository's active main build is a self-hosted Stage-2 compiler, driven by
scripts/build.sh and a trusted NOQERI_STAGE0 seed. It does not build using CMake.
The C++17/CMake bootstrap is a separate compatibility/tooling path, so the new
native SQL host is supplied through a standalone CMake 'noqerisql' executable.
Runtime/stage2-cli.mjs explicitly delegates SQL commands through
NOQERI_SQL_ADAPTER. This is an optional host adapter, NOT a Noqeri-native
database compiler implementation.

IMPLEMENTED CHANGES IN THIS PULL REQUEST
A. Standard SQL:
- Compiler/bootstrap/sql_host.cpp and Include/noqeri/sql.hpp: SQL executor using
  real SQLite3 and PostgreSQL/libpq libraries instead of .nqd syntax.
- Tools/sql/noqerisql_main.cpp: dedicated adapter binary.
- Compiler/bootstrap/cli_host.cpp: optional 'noqeri sql' command in C++ bootstrap.
- Runtime/stage2-cli.mjs: opt-in SQL command delegation for actual Stage-2 CLI.
- CMakeLists.txt: optional dependencies; require-both configuration, adapter
  executable and installation, tests.
- PostgreSQL currently supports ONE statement per input file (PQexecParams),
  enforced TLS verification and transaction status handling. No live server test.
- SQLite supports standard SQL files containing multiple statements.

B. Durability and concurrency:
- SQLite uses actual SQLite WAL, synchronous=FULL, VFS locks, busy timeout 5 s,
  BEGIN IMMEDIATE, COMMIT on success and rollback on failure.
- Legacy host no longer deletes committed DB before rename. On POSIX it now
  fsyncs temporary file, atomically renames in the same directory and fsyncs
  its parent directory; Windows uses MoveFileExW replace + write-through.
- Legacy writer lease via atomic lock directory. Stale lock requires careful
  administrative inspection after a crash; do not blindly delete a live lock.

C. Data integrity and validation:
- Legacy database decoding applies a 64 MiB file cap, table/row/column count
  limits, duplicate row-field rejection, boolean metadata flag checks, read
  error checks and stricter numeric/boolean persisted value decoding.
- Existing legacy schema checks now compare names, types and column flags,
  not just column count.
- SQL scripts reject empty, missing, oversized (>1 MiB) and NUL-containing
  inputs. SQLite enforces foreign keys and resource limits.

D. Query safety:
- Prepared query policy counting ignores question marks inside quoted strings,
  identifiers, -- comments and /* ... */ comments and rejects unfinished
  single/double quotes and block comments.
- SQLite managed script forbids unbound placeholders, explicit transaction
  commands/savepoints, PRAGMA, ATTACH and DETACH; defensive mode and trusted
  schema OFF.
- PostgreSQL uses extended protocol and rejects multi-command scripts.
- CLI does not accept untrusted data bindings. Applications must use actual
  sqlite3_bind or libpq PQexecParams parameter binding for user input.

E. Tests added:
- tests/noqerisql_policy.nqr: dialect and placeholder policy.
- tests/noqerisql_smoke.sql and noqerisql_rollback.sql: SQLite SQL and failure.
- tests/noqerisql_integration.mjs: 64 parallel writer processes; uniqueness
  rollback; blocked COMMIT; prepared placeholder rejection; PRAGMA/BEGIN
  rejection; FK enforcement; malformed SQLite file; oversized SQL file.
- CMake registers native and language policy tests, and optional Node tests.

STATUS OF THE SEVEN ORIGINAL FINDINGS
1 SQL compatibility: PARTIAL — real SQL via SQLite/libpq; dialect bridging,
  app-facing bound statement API, Noqeri-native execution not implemented.
2 Durability: MITIGATED — real SQLite WAL; legacy fsync/atomic replacement.
  Power-loss and Windows recovery evidence still missing.
3 Transactions: MITIGATED — SQLite VFS cross-process coordination verified
  locally. PostgreSQL server and legacy lock crash-recovery not validated.
4 Data integrity: PARTIAL — size/count caps and SQLite integrity;
  legacy format has no end-to-end checksum/MAC and recovery gate.
5 Schema validation: FIXED for direct legacy schema redefinition checks.
  Further corrupted legacy persisted schema checks remain desirable.
6 Query safety: IMPROVED — comment/string parsing and fail-closed script
  rejection; complete SQL lexical/dialect conformance is not claimed.
7 Production testing: PARTIAL — committed tests and isolated Linux evidence.
  Self-hosted bootstrap, Windows/macOS, Postgres server, fault injection
  and full suite are not complete.

DESIGN SOURCE
User supplied 'NoeSQL 1.0 Hybrid Query Language & Typed Database API —
Design Specification v0.1'. This implementation follows its separate .noe
script and .nqr typed-query concepts, but does NOT claim full spec completion.

COMPILER DECISION
The normal main build is already Noqeri self-hosted in Compiler/selfhost/*.nqr;
scripts/build.sh requires a trusted NOQERI_STAGE0 seed and emits .nqo.
Retain archived C++ bootstrap provenance until fixed-point reproducible
compiler bootstrapping passes. No C++ removal is justified by current evidence.
Web remains .nqo. No actual full-stack/OS runtime readiness is established.

FILE FORMAT DECISION
.nqr = Noqeri main source
.nqo = portable Noqeri compiler/web output
.noe = new NoeSQL query/schema script
.nqd = new NoeSQL reference DB snapshot (NOED1 JSON/checksum)
Legacy NoqeriDB .nqd *script* and .nqdb *database* continue on separate
compatibility command and are NOT automatically migrated to NoeSQL.
SQLite and PostgreSQL use distinct formats and independent host adapters.

IMPLEMENTED IN THIS FEATURE BRANCH
- Database/noesql_lexer.nqr: native token scanner with spans/diagnostics.
- Database/noesql_parser.nqr: native bounded precedence expression parser.
- Database/noesql_ir.nqr: native typed query/catalog record contracts,
  lookup helpers, schema-version and predicate safety validation.
- Database/noesql.nqr: native module facade.
- Runtime/noesql/compiler.mjs: runnable JS reference lexer, recursive-descent
  declarations, precedence expressions, line/column diagnostics and AST.
- Runtime/noesql/engine.mjs: reference catalog, typed semantic validation,
  shared row executor for scans, projections, filters, sort, offsets, limits,
  insert, update, delete; foreign keys/unique and checksummed snapshots.
- Runtime/noesql/cli.mjs and Runtime/stage2-cli.mjs: new 'noqeri noe'
  reference command with .noe / .nqd paths.
- tests/noesql.test.mjs (16 offline tests), tests/noesql_ir.nqr (unverified),
  tests/noesql_fixture.noe and scripts/test-noesql.sh (no GitHub Actions).
- Doc/NOESQL.md documentation.

MISSING RELEASE REQUIREMENTS / HONEST LIMITS

- Reference storage engine uses Node.js, not exclusively Noqeri.
- Complete self-hosted build/doctor/tests and native/web/OS targets not run.
- No Github Actions were used. No PR merge, v1.0 tag or stable release created.
