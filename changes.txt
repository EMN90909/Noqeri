CHANGES ACTUALLY IMPLEMENTED
1. Compiler/bootstrap/noqeridb_host.cpp: removed destructive deletion of an
   existing committed database before renaming the temporary snapshot. POSIX
   rename can replace atomically; platforms without overwrite-on-rename fail
   safely instead of deleting the original. Full cross-platform durability
   (directory fsync, Windows replacement, crash recovery) is still outstanding.
2. Compiler/bootstrap/noqeridb_host.cpp: existing table definitions now compare
   every column's name, type, required, unique, and key flags, not just count.
3. Compiler/bootstrap/noqeridb_host.cpp: persisted schema metadata now rejects
   malformed out-of-range boolean flags; read stream failure is reported.
4. Database/query.nqr: placeholder counter now ignores ? within single-quoted
   SQL strings, double-quoted identifiers, -- comments, and /* */ comments,
   including doubled quote escaping.
5. Database/dialect.nqr: added explicit dialect identifiers and parameter
   limits for embedded, SQLite, and PostgreSQL backend TYPES (policy only).
6. Database/NOQERISQL.md: documented architecture, migration, compatibility
   and security acceptance criteria without claiming unavailable SQL support.
7. Database/README.md: adopted NoqeriSQL subsystem naming while retaining the
   existing NoqeriDB CLI/API/file format.
8. tests/noqerisql_policy.nqr: new policy/placeholder regression test source.

CRITICAL / HIGH FINDINGS STILL OPEN
C1. Legacy .nqd parser is NOT standard SQL and .nqdb is NOT a SQLite database.
    SQLite engine integration and PostgreSQL client/protocol are unimplemented.
C2. Legacy host has no robust multi-process writer lock or MVCC; concurrent
    writes can silently race and lose data.
C3. Whole-file snapshot writer has no durable cross-platform atomic replace,
    parent-directory fsync or WAL-based crash-recovery protocol.
H1. loadState uses unbounded parsing/allocations and insufficient quotas on
    table counts, rows, strings and file size; malformed count handling remains.
H2. Persisted records lack cryptographic checksums/MACs and verified recovery;
    the separate policy files are not wired into legacy host execution.
H3. No parameter-binding API in the legacy host; the custom script interpreter
    should not be called a standard SQL prepared-statement implementation.
H4. Query handling lacks full SQL lexer rejection of unterminated strings or
    comments and support for PostgreSQL positional/named parameters.
H5. Legacy script WHERE validation and mutations need comprehensive adversarial
    tests; the interpreter remains a limited non-SQL data language.
H6. Existing .nqdb compatibility/migration and database backup/restore have no
    end-to-end migration verification gate.
H7. Safety policy tests alone are not storage engine integration tests.

IMPLEMENTATION PLAN / RELEASE GATE
P0: Complete snapshot durability, safe locks, quotas, strict file decoder,
    corruption detection, fail-closed recovery, and cross-platform tests.
P1: Implement SQL parser/typed AST and prepared binding API, plus real SQLite
    adapter, SQLite integration tests and explicit feature-negotiation.
P2: Implement PostgreSQL adapter with verified TLS, secure authentication,
    prepared protocol, parameter type mapping and transaction handling.
P3: Backups and migrations with verification, SQL conformance tests, fuzzing,
    fault injection, benchmarks, and reproducible platform CI evidence.

- The new dialect names are policies, not working SQLite or PostgreSQL drivers.
- Do not advertise NoqeriSQL as production-ready.
